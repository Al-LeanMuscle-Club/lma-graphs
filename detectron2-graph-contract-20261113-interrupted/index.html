- Step: launch preparation.
- What happened: `ExecutionController(check_validation=None)` means validation off
  (`leaf_test_validity.validate_policy(None)` returns None), while `nanolize review` without
  `--check-validation` means the default policy (`requested_policy(None)` returns `{}`). The

  validation off.

- Step: launch preparation (writing the `test_template`).
- What happened: `/tmp/lma-detectron2-env` has a `.pth` hook that makes
  `detectron2.projects.point_rend` resolve to
  `.../detectron2-nanolized/projects/PointRend` (an earlier compressed checkout) when Python starts
  with site hooks. A plain `python -m pytest {test_file}` template would test the wrong code.
- What I did: the template runs `python -S -B designed_test.py {test_file} --junitxml={junit_path}`

  dependency site added explicitly, as the frozen upstream checks of this profile already do.

O-5 Designed tests need the native extension in trees that have no build

- Step: launch preparation.
- What happened: test design and knockouts run in fresh exports of the original (no `.git`, no
  ignored files), so `detectron2._C` is not built there, and every test that touches

  extension built from its own sources by the preparation recipe. A candidate with changed native
  source never borrows the original binary.
