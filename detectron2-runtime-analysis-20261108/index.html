03 / THE BOTTLENECKS

工作重心偏向流程维护

四个主要原因，既有完整重写的必要成本，也有可以减少的交接与重复审查。

01

审查拆得过细

修复工具、检查方案、执行命令、检查结果被分给多个新会话。一个小问题可能触发“作者 → 审查者 → 执行 → 新审查者”的完整循环。

02

验收工具故障阻挡了重写

反复处理的是路径、缓存、锁和测试进程等运行问题。它们会影响可信验证，但应尽量由稳定的工具一次解决。

展开 4 个实际阻塞点
  • 5 个生成的 .pyc 文件，共约 66.9 KB，改变了固定目录的哈希。
  • 同一个目录的相对路径和绝对路径被判定为异常差异。
  • 临时目录长 169 字节，最终 Unix socket 路径达 201 字节，导致创建失败。
  • 读取 /proc/1/ns/pid 权限失败，实际测试进程尚未启动就退出。
03

全功能与旧环境兼容有真实成本

106 个能力模块、447 个生产文件，范围还覆盖 CUDA、原生扩展、项目扩展和安装行为。旧 Caffe2 构建本身约耗时 48 分钟；首次重写无法读取原源码，需要先补齐知识。

04

有限并行额度被辅助工作占用

当时最多同时运行 3 个工作 agent。辅助审查占用名额，而重写还包含文件归属规划、等待依赖、共享模块连接等串行步骤。

这是流程设计建议，尚未应用于本次运行；没有据此声称已经加速或放宽完整功能验收。

01

将机械性检查固化为程序

规范化路径，区分稳定输入与生成缓存，可靠处理临时目录和进程清理，减少反复调用模型判断。

02

按一批有意义的变更独立审查

把方案和实际证据集中交给审核者。保留作者与验收者的独立性，减少每个小步骤都换新会话。

03

让已就绪模块尽早开始重写

旧环境专项验证可与独立模块并行。未知项继续明确记录，最终完整验收仍需满足，不把未验证当作通过。

04

合并文件归属规划与实现交接

集中分配文件后让作者直接实现，减少单独的“声明文件 → 等待批准 → 实现 → 连接”会话。

05

给准备与验收工具修复设置独立预算

现有代码修复次数限制约束不到这些前置循环。为它们单独设定时间或迭代上限，达到边界时保存进度、报告未解决项，再决定下一步。

最值得优先压缩的，是重复审查与串行等待。
继续增加 agent 数量，未必能解决这些交接成本。

这是基于本轮记录的判断；尚无对照实验，无法可靠承诺节省的时间或 Token 比例。
