37.50% 的增长来自 JSON 序列化

两份 cases.json 解析后得到的数据完全相同。旧文件为 5,783 个 Token，新文件为 10,508 个 Token。排版与序列化方式造成了 4,725 个 Token 的差异，没有增加基准用例。

Python 代码仅增加 2.75%

生产 Python 文件合计为 65,641 → 67,446 个 Token。两个分支都包含 35 个 Python 文件。浏览器 JavaScript 另外增加了 4,996 个 Token；新文件包含更多预设数据和界面逻辑。

冻结的文件分类规则将原版七个 SVG 文件及 llms.txt 的 69,506 个 Token 归为配置。删除它们解释了两次实验总体压缩率中的很大一部分。补充口径在原版和候选版中排除完全相同的八个路径：106,460 → 76,443 / 88,976。必需的 JSON 数据和其他新增文本仍计入统计。仅源码口径也会受到把 Python 数据字面量迁移到 JSON 的影响。
统计规则与预算结果

三个提交的代码均使用 tiktoken 0.12.0、cl100k_base、逐文件独立的原始文本分词，以及冻结的源码／配置分类规则重新统计，结果与历史记录完全一致。这是代码体积的 Token 统计，与模型执行消耗的 Token 不同。

旧版源码为 67,087 个 Token，上限为 49,519，超出 17,568；源码与配置合计为 76,443，上限为 86,223，已达标。本次源码为 74,176，合计为 89,044。继承的通用 50% 字段仅作为参考，因此功能验收通过后停止优化符合本次要求。

05

绿色检查遗漏的兼容性差异。

本次对比的新发现：对于旧引擎不支持的 embed() 操作，两个重构版本都与原版不同。

这不是历史验收中新增的一项失败。 已有的 39/39 结果仍准确描述了当时声明的检查。此次单独的定向探测发现了检查未覆盖的异常类型与执行顺序差异。
实现版本抛出的异常抛出异常前的调用
原版ValueError ↗尚未绑定引擎或执行生命周期检查
旧版NotImplementedError ↗生命周期检查（check）
本次RuntimeError ↗绑定引擎（bind）

如果调用方通过捕获 ValueError 来处理不支持的操作，在两个候选版本上的行为都会改变。本次版本还会先绑定引擎，再拒绝请求；原版则先检查引擎代数。这说明绿色报告不能直接等同于完整的 API 行为等价。

这个问题是怎样验证的？

从原版、旧版和本次提交中通过 AST 提取 embed 方法，保留方法体不变，并以第 2 代引擎执行。引擎绑定和旧版生命周期检查被替换为记录调用顺序的桩函数。无需下载模型、加载原生库或修改分支，就能确认异常分支与执行顺序。这是一个范围很小的分支探测，不是完整的旧引擎集成测试。

建议后续处理： 恢复原版异常类型及校验顺序，把回归断言加入冻结约定，再运行受影响的 API 检查。本次对比没有修改两个代码分支。

观察到的改善

本次 Python Token 数略多，但函数数量和很长的代码行更少。运行时将原生绑定和结果依据检查拆为独立辅助模块，定向修复主要围绕具体接口。浏览器界面和训练路径也有了更充分的执行证据。

仍然不能确定的部分

这些数据只是帮助审查，不是可读性评分。两个代码树均能解析，保留 Apache-2.0 许可证，使用真实数值计算／训练实现，此次扫描未发现直接的动态代码执行调用。旧版的有限审查确认保留了 44 个带类型注解的可调用接口和 143 个类字段注解；注解数量本身不能证明兼容性。

两个候选版本都没有完成与原版配对的真实任务成本测量，因此尚不能证明认知负担降低，也不能证明后续 agent 使用它们时会节省 Token。

保留功能优先的停止条件

没有硬性比例要求时，行为与安装验收通过后停止纯体积优化。旧版从第 2 次尝试起就满足合计体积目标，但最终仍未通过功能验收；额外的源码单独上限是另一项约束。

02

修复反馈必须具体、可执行

本次第一次修复仍停留在 32/39。后来具体的行为事实推动结果依次达到 35、38 和 39。应先等待这些事实，再启动下一次重写，并将反馈保存在控制器记忆中。

03

检查有效性后复用基线

本次三次完整基线耗时约 36 分钟。仅修改候选代码，不一定需要使未改变的原版基线失效。知识／约定修订应保留证据绑定；绑定仍有效时，应避免重复采集。

04

迭代中定向重测，最后完整验收

五次完整的 39 组比较花费约 65 分钟。修复期间可先运行受影响的检查，最终保留一次完整重跑，同时确保未解决的失败不能通过选择测试而被隐藏。

05

验收前补齐必要数据

将保留数据放在重写上下文之外，再由可信宿主侧在验证前恢复。统一 JSON 序列化规则可以减少产物 Token，无需额外模型调用；比较预算前应记录清楚统计规则。

06

把发现的盲区加入验证约定

审查暴露问题时，应补充异常类型、校验顺序、自动副作用及兼容路径。269 个用例通过，仍没有发现旧引擎 embed() 异常类型的变化。
