37.50% of the growth is JSON serialization

Both cases.json files decode to exactly the same data. The old file is 5,783 tokens; the new file is 10,508. Formatting and serialization account for a 4,725-token difference, with no additional benchmark cases.

Python code grew only 2.75%

Across production Python files: 65,641 → 67,446 tokens. Both branches contain 35 Python files. The browser JavaScript accounts for another 4,996 tokens; the new file includes a larger preset catalog and more UI logic.

The frozen classifier counts 69,506 original tokens from seven SVG assets and llms.txt as configuration. Removing them explains much of both headline reductions. The secondary comparison excludes exactly the same eight paths on both sides: 106,460 → 76,443 / 88,976. It keeps required JSON data and other newly added text in the count. Source-only reduction is also affected by moving Python data literals into JSON.
Counting rules and budget outcome

All three committed trees were recounted with tiktoken 0.12.0, cl100k_base, independent per-file raw-text tokenization and the frozen source/configuration classifier. The results exactly match the archived totals. This is code-size tokenization, unrelated to model execution token usage.

Old source: 67,087 tokens against a 49,519 ceiling — 17,568 over. Old combined: 76,443 against 86,223 — passed. New source: 74,176; new combined: 89,044. The generic inherited 50% metadata was advisory, so stopping after functional acceptance complied with the new request.

05

A compatibility gap the green checks missed.

New finding from this comparison: the unsupported legacy-engine embed() path differs in both rewrites.

This is not a newly failed historical test. The archived 39/39 result remains accurate for its declared checks. A separate focused review probe found an untested exception-type and ordering difference.
ImplementationRaised exceptionCalls before raising
OriginalValueError ↗No bind/check before error
OldNotImplementedError ↗check
NewRuntimeError ↗bind

A caller catching ValueError for an unsupported operation will behave differently on both candidates. The new version also binds the engine before rejecting the request; the original validates the generation first. This is a concrete reason not to equate a green report with complete API equivalence.

How this finding was checked

The original, old and new committed embed method bodies were extracted by AST and executed unchanged with generation 2. Engine binding and old lifecycle checking were replaced by tracing stubs. The results confirm the exception branch and ordering without downloading models, loading native code or changing either branch. This is a narrow branch probe, not a full legacy-engine integration test.

Recommended follow-up: restore the original exception type and validation order, add a regression assertion to the frozen contract, and replay the affected API checks. This comparison does not modify either code branch.

What improved

The new Python tree has fewer functions and fewer very long lines despite slightly more Python tokens. Its runtime separates native bindings and grounding helpers; targeted repairs address concrete interfaces. The browser surface and training paths have stronger execution evidence.

What remains uncertain

These are inspection aids, not a readability score. Both trees parse, preserve an Apache-2.0 license, use real numerical/training code and have no direct dynamic-code calls in this scan. The old bounded audit preserved 44 annotated callable interfaces and 143 class-field annotations; annotation counts alone do not prove compatibility.

No completed paired task-cost benchmark exists for either candidate, so neither reduced cognitive burden nor downstream agent-token savings has been demonstrated.

10

What this experiment supports.

Keep the useful policy change, then remove specific sources of wasted work.

01

Keep functionality-first stopping

Stop volume-only optimization after behavioral and installation acceptance when no hard ratio is requested. The old candidate already met the combined size target by attempt 2, yet still failed functionality at the end. The additional source-only guard was a separate constraint.

02

Require actionable repair feedback

The new first repair stayed at 32/39. Precise semantic facts later moved the result to 35, 38 and 39. Await those facts before starting another author; retain the feedback in the controller’s memory.

03

Reuse baselines with explicit validity checks

The new run spent 36 minutes on three full baselines. Candidate-only changes need not invalidate an unchanged original baseline. Knowledge/contract revisions must retain evidence binding; avoid redundant recapture when those bindings remain valid.

04

Target repairs, then run a final full check

Five full 39-group comparisons took about 65 minutes. Run the affected checks while iterating, keep the final complete replay, and ensure unresolved failures cannot disappear through test selection.

05

Integrate required data before acceptance

Keep reserved fixtures outside author contexts, then restore them through the trusted host before validation. Canonical JSON serialization can reduce artifact tokens without another model call; record the policy before comparing budgets.

06

Expand contracts at observed blind spots

Add exception types, validation order, automatic side effects and compatibility paths when a review exposes a gap. Passing 269 cases did not catch the legacy embed() exception change.

The observations are consistent with less budget pressure helping convergence, but do not isolate its causal effect. New accumulated knowledge, a different harness, richer checks, owner feedback and task-evaluation settings also changed. The main demonstrated gain is a better tested result with fewer rewrite calls, not a dramatic wall-clock speedup.
