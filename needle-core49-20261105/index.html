How it was verified

  1. Pin the unchanged upstream commit and re-review the existing Graphify evidence for the core scope.
  2. Freeze original unit tests, selected adaptations, schemas and deterministic native output checks before authoring.
  3. Start a fresh author with no original implementation, tests or Git history. Supply selected contracts and approved external binary assets.
  4. Compare retained behavior, repair observed regressions, and rerun the final retained check set.
  5. Build a wheel, install into a fresh environment outside the source checkout, and validate import origins and the console entrypoint.

Ordinary checks include 105 upstream test cases across schemas, grounding, model loading, workers, downloads and actual native inference, plus schema output comparison, native output/embedding comparison, telemetry opt-out, schema construction time and package checks. Per-module evidence and the exact recorded final outcome are in the graph below.

Agent-designed task evaluation remained disabled throughout. There were no development-task or hidden-task comparisons.

Verification and repair history

Early regressions exposed missing compatibility details in the initial knowledge package: module-level runtime hooks, engine catalogs and paths, and observable schema shapes. The verifier translated these findings into semantic clarifications for the author; original implementation and test bodies stayed on the verification side.

Every attempt was checked against the same frozen original contract. Earlier failures remain recorded; only the final candidate is accepted. Repair screens can defer unrelated checks, but final acceptance requires rerunning every retained group.

Limits of this result

  • Passing the recorded checks is evidence for the retained scope, not full semantic equivalence.
  • Speech, training, hosted services, browser playground, demonstration environments and maintainer release automation are out of scope; their tests are not counted as passes.
  • Native inference was checked on Linux ARM64 in a 16-CPU Slurm allocation with the same external engines and pretrained assets for both versions. Other operating systems and devices were not exercised end to end.
  • The original operational subtotal excludes only identified standalone SVG illustrations and llms.txt; candidate text receives no additional free exclusions. Both original totals and the shared tokenizer are provided.
  • Mapped selected-source size is an estimate: shared files can include excluded branches. Scope-removal and rewrite reductions must not be confused.
  • Agent-designed development tasks, hidden tasks and task-effort token comparisons were disabled. No cognitive-cost improvement is claimed.
  • Source-free authoring is a supplied-input boundary, not an OS-enforced sandbox; original source/tests/history were not supplied to the fresh author.
  • Portable verification bundle export is unavailable because the local check recipes include absolute verifier paths; local frozen verification evidence is retained.
