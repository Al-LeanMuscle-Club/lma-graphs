Read the evidence carefully

  • The source-only size target was not reached. The lower combined percentage must not be presented as achieving a halving of the implementation.
  • The run consumed its configured limit of 20 implementation attempts, including interrupted invocations. The final candidate is delivered with the unmet source target explicitly recorded; no additional feature exclusions were introduced.
  • Passing finite tests does not prove complete semantic equivalence or equal performance.
  • Verification includes CPU and the separately reported CUDA checks. Apple Metal and long-running training quality remain unverified.
  • Hosted paid cloud APIs are checked with mocked transport; no live paid-service equivalence is claimed.
  • Live microphone devices, long audio streams, every speech language, Windows/macOS/Android/musl device deployment and real release publication were not exercised.
  • Browser interaction checks use local deterministic HTTP responses. They validate controls and API wiring, not live paid generation or native inference inside the browser test.
  • HTTP pipeline checks execute the real local handler and training worker with service doubles for inference, paid generation, training and export; they establish request/status/artifact wiring, not model quality.
  • Performance measurements cover only the workloads shown here. They do not establish general training, GPU or service performance. Actual agent effort was not assessed.
  • Per-capability code counts use unions of mapped files. Shared files can appear in multiple nodes; do not sum nodes.
  • Original environment example records are preserved unchanged in a JSON data file and counted as configuration. Moving those literals out of Python is not a reduction of their content.
  • The harness combined inventory counts README SVG artwork and llms.txt as configuration. Their removal is not implementation simplification; the supplementary operational total excludes these documentation files from both versions.
  • The original CPU implementation has four quantized JAX/MLX parity failures in this environment; they are shown separately from regressions. CUDA baseline outcomes, when present, are compared separately.
  • The author received source-free semantic knowledge and owner-reviewed clarifications. The owner consulted original source; author source isolation was procedural, not an OS security guarantee.
  • The native harness overall result remains unverified. Its graph evidence retains any unresolved checks or environment/contract binding issues; individual passing checks do not override that status.
  • The historical native-baseline environment fingerprint could not be reproduced exactly. The original record was kept unchanged, so the native verifier remains unverified even when all its check groups pass. The separately paired upstream and numerical comparisons are reported with their own bindings.
  • GPU verification uses the recorded JAX 0.10.2 / CUDA 13 environment. The original and candidate CUDA 12 package extra was preserved but was not accepted as a validated GB200 environment; a CUDA 12 diagnostic was stopped after a runtime compatibility warning.
  • Highest-dot-precision CUDA checks are an additional controlled numerical comparison. They do not change production defaults or replace the separately displayed default-precision results.
  • Additional deterministic CUDA comparisons disable compilation autotuning and exclude nondeterministic operations in both arms. Production defaults remain unchanged. Original repeated compilations also showed numerical variation; default failures remain visible and are not relabeled as passes.
