03 / IMPLEMENTATION

设计与实现，一项一项对照

M01 — M12

显示 12 项

M01

Controller 替代中间固定策略

新提交默认记录 engine=agent-controller-v1，worker 进入 Controller。Agent 选择基线、重构、验证、修复、恢复、继续或交付。原有 Submit、worktree、Local/Slurm、取消和预算入口保留。

✓ 已完成
M02

提取共用工具

33 个可组合操作，通过 CLI control 与 MCP controller_operation / controller_state 共用核心。包含工作区、契约、环境准备、候选、检查、覆盖、代码度量、性能检查、任务评测和管理。行为比较保留“执行检查并比较”的显式组合语义，不隐式修复。

✓ 已完成
M03

去掉默认隐式修复

CLI 的 verify、scope-verify、verify-bundle、report 及对应 MCP 默认只验证或渲染。只有 --repair / auto_repair=True 才进入显式修复组合。基线捕获也不再隐式执行环境准备。

✓ 已完成
M04

契约、检查、环境可修订

增加静态修订请求与独立 owner 授权入口，可在同一任务追加检查、替换完整知识。原配置、范围与预算不变；授权链、契约与环境版本绑定证据，历史验证不会复用。支持暂停/授权/恢复、知识更新的中断恢复以及旧候选接收当前知识。

✓ 已完成
M05

严格标准成为可调用工具

evaluate_acceptance 提供 behavior / delivery 标准，返回通过、缺口和实际失败，不选择下一步。覆盖审计可单独调用；不足不再阻止新 Submit。最终交付仍诚实保留缺口，发布权限和事实标准不因 agent 决策而绕过。

✓ 已完成
M06

Agent 决定修复、优化与停止

修复、优化、恢复和交付均为显式操作。没有工具因检查失败自动再次调用 author。保留总期限、runner 超时、显式 author 上限、优化上限和取消。

✓ 已完成
M07

拆分任务评测

独立设计、保存 suite、执行一次 solver、延后独立评分、比较已评分配对观测；已有完整重复评测保留为可选组合。隐藏验收在 solver 完成后才进入评分工作区。关闭评测会拒绝所有相关入口。不同 suite/试验共享 owner 的已观测 token 总预算。单次配对不冒充完整成本改善结论。

✓ 已完成
M08

显式候选管理

保存候选、按指定文件合并候选部分、恢复及带理由选择候选。不会自动选择 tokens 最少的版本。合并拒绝路径越界、重复文件和 oracle 冲突；恢复后旧观测不自动成为当前验证。

✓ 已完成
M09

批量、异步与并发

增加独立实现工作区、受 owner 上限控制的并行会话、独立回执及草稿归档。一批请求共享 author/optimization 预算，失败保留成功分支；显式按文件合并后重新验证。实际子进程重叠与按身份取消已验证。同一验证候选仍串行，不包含自动跨节点分配。

✓ 已完成

06 / GET STARTED

新任务默认启用，旧 runner 需要适配

调用方式

CLI 与 MCP 使用同一操作核心。执行操作需要已授权的 job 配置；相同 request ID 与参数不会重复执行。

CLI · 示例路径
nanolize control /private/state/jobs/JOB_ID --json

nanolize control /private/state/jobs/JOB_ID capture_baseline \
  --request-id baseline-v1 --allow-execution --json

迁移时留意

  • 控制调用读取 context.json 与 knowledge/，写出 decision.json。
  • 实现调用继续使用 .nanolize-rewrite。旧的纯代码写入脚本不能直接当 Controller。
  • 验证默认不修复，需显式使用 --repair 或 auto_repair=True。
  • 历史任务保持兼容路径。旧工具契约不匹配时，仍需原版本运行时恢复。

延续 main 的 source-free 实现边界；仓库文字不能成为执行授权。目录隔离与摘要校验不等于 OS 沙箱。
