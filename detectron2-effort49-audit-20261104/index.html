排版归一化

Python 行数降幅：69.24% → 56.41%

两边统一使用 Black 26.10.0、88 字符行宽后，原版为 68,303 行，候选为 29,773 行。可见原始行数对排版敏感。

再移除注释和 docstring，用同一 AST 输出方式计算，为 30,815 → 18,452 行，减少 40.12%。40.12% 仍不是“真实架构压缩率”：它只覆盖 Python，仍受配置迁移、依赖委托和行为遗漏影响。

解释性内容

注释与 docstring 占行减少 98.87%

Python 纯注释行：4,097 → 31。Docstring 占用行：12,732 → 160。两项合计：16,829 → 191。

消失的内容包含 Hook 生命周期、计时约束、预训练模型归一化参数的原因等使用知识。删除过期解释合理；丢失有效契约，会把理解成本转移给下一位维护者。

03 / BEHAVIOR

有些差异，已经改变了行为。

以下三类问题来自原版与候选源码的直接比对。尺寸公式和分支差异可以静态确定；本次没有新增运行验证，也不推测精度损失的大小。

01
静态确认 · 数值与形状

TensorMask：边缘输出丢失，采样位置改变

原版 SwapAlign2Nat 使用 ceil(H / λ)，新版 C++ 和 Python fallback 都使用向下取整。原 API 没有要求 H、W 必须被 λ 整除。

合法输入N=1 · C=4 · H=W=5 · λ=2
原版(1, 16, 3, 3)
→
压缩版(1, 16, 2, 2)

即使尺寸可以整除，候选坐标公式仍比原版多偏 (λ − 1) / 2 个输入像素。λ=2 时，两轴各偏 0.5 像素。因此，这不是仅移除 CUDA 文件，而是替代实现改变了算子的数学行为。

展开公式与源码证据
原版：y × λ + v − Vout / 2 + 0.5
候选：(y + 0.5) × λ − 0.5 + v − (Vout − 1) / 2
    = y × λ + v − Vout / 2 + λ / 2
原版输出尺寸 ↗原版采样坐标 ↗候选 C++ ↗候选 Python ↗
02
静态确认 · 项目入口

PointRend / DeepLab：共享入口抹掉了必要差异

候选统一使用 ProjectTrainer。评估器选择变为语义分割使用普通 SemSegEvaluator，其余使用 COCOEvaluator，遗漏原有 LVIS、Cityscapes 专属分发。

专用数据增强也没有完整接入。PointRend 的配置仍声明类别面积约束裁剪和 SSD 颜色增强，但共享入口使用默认 mapper，没有消费这些设置。相关类仍存在，不代表原来的训练入口仍能使用它们。

查看调用链与证据

03
静态确认 · 导出契约

Caffe2：旋转框和关键点转换被简化掉了

候选统一截取框的最后四列构造 Boxes。对于原版支持的五列旋转框 (cx, cy, w, h, angle)，这会丢失旋转框语义。

关键点输出直接赋值，遗漏从 [N, 4, K] 到 [N, K, 3] 的转换，以及 kps_score 热图处理分支。候选导出 forward 也未保留关键点输出。此结论针对这些具体路径，不代表整个 Caffe2 系统均无法运行。

候选输出转换 ↗原版旋转框与关键点处理 ↗
性能风险 · 尚未实测

能在 GPU 上运行，不等于保留了原有执行特性。

新版 rotated ROIAlign 逐 ROI 循环，并从 CUDA 张量读取 Python 标量，存在同步开销。Rotated NMS 则从紧凑 bitmask 改为完整的 N×N IoU 矩阵。

仅 float32 IoU 矩阵的理论存储量约为 4N² 字节，而原 bitmask 约为 N²/8 字节，前者约 32 倍。这不是实测峰值内存比，更不是“慢 32 倍”。原版本来也会把 bitmask 传到 CPU，不能把 .cpu() 本身当成新回归。

ROIAlignRotated ↗Rotated NMS ↗

合理的 CUDA 复用应保留：deformable convolution 委托 Torchvision、用 ATen 张量算子替代自写内核，本身都可以是有效简化。候选没有 .cu 文件，不等于删除了全部 GPU 功能；必须依据具体行为判断。

多行合一，可以接受吗？

简短 getter、空方法、短表达式适度合并通常可以接受。本次 Python 扫描未发现分号语句挤压；但部分表达式很长，缩短的是排版。应统一格式后计量，让选择换行风格不再产生压缩奖励。

保留原 API 路径也不等于没有重构。判断重点应是内部逻辑是否重复、概念是否减少、修改一个功能需要跨越多少层，而不是仅看文件数或单文件长度。

06 / NEXT DESIGN

让验收奖励真正的简洁。

此次运行的 harness 已有“禁止 minification、不得删能力”的文字要求，但可计算的尺寸门槛仍主要依赖物理行数。删除说明、压行或较短的替代路径，都可能得分，而损失未必被检查覆盖。

01

消除排版与说明删除的奖励

两边使用统一格式；实现、配置、数据和解释器共同计量。把有效契约文档的保留作为独立检查，不把它算作需要消灭的冗余。

02

按行为验收，不按名称验收

能力约束应包含形状、数值、设备、梯度、项目入口与必要外部行为。配置加载、可导入、forward、训练和性能分别标记；没有证据的路径保持未知。

03

要求结构收益可解释

每项主要缩减说明消除了哪段重复逻辑、哪层间接调用，或让修改一个功能少理解哪些模块。共享抽象应显式保留差异，避免通用分支静默替代专属行为。

04

把 LOC 作为辅助结果

用结构指标发现问题，再通过少量代表性理解、诊断、修改和执行任务检验成本。任务成功率与 token 消耗共同看，保留 heldout，不把单一静态指标当认知负担本身。

要减少的是需要理解的概念、重复逻辑和跨模块追踪。
更少的行数，是可能的结果；更简单的系统，才是目标。

审查方法

Python 统计
采用与源码预算一致的文件选择和测试排除口径。Black 26.10.0、行宽 88；AST 口径先移除模块、类、函数 docstring，再使用同一 Python 3.13 的 ast.unparse 输出。两项只适用于 Python；不与全语言、含运行资源的 52.58% 混用。
如何解读
不同口径相互重叠，不是可相加的“压缩来源占比”。注释占行不等于注释质量；AST 行数不等于语义复杂度。文件更多、路径保留或 CUDA 文件消失，都不能单独证明重构优劣。
验证证据
历史实验按最终公开报告引用；静态确认与未实测风险分别标记。没有根据单张图推理、局部测试或功能图状态声称完整等价。
